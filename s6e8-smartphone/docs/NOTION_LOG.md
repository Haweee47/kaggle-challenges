### 💡 오늘 배운 ML 개념 1가지 — 데이터 누수 (Data Leakage)

**모델이 학습 시점에 "알아서는 안 될 정보"를 미리 엿보는 현상.**

교차검증에서 가장 흔한 형태는 **전처리 통계값을 전체 데이터로 계산하는 것**이다.

```python
# ❌ 틀린 방법
train[col] = train[col].fillna(train[col].median())   # 전체로 중앙값 계산

# ✅ 올바른 방법
med = X_tr[col].median()           # 학습 폴드에서만 계산
X_tr[col] = X_tr[col].fillna(med)
X_va[col] = X_va[col].fillna(med)  # 검증 폴드에는 '적용'만
```

전체 데이터로 중앙값을 구하면 **검증 폴드의 값이 중앙값을 통해 학습에 새어 들어간다.**
결과는 "CV 점수는 좋은데 리더보드에서 무너지는" 전형적인 실패다.

**이번 대회에서의 적용**: `src/preprocess.py`의 `impute_median()`을 *(채워진 데이터, 사용한 중앙값,
사용한 최빈값)* 을 함께 반환하도록 설계했다. 계산한 값을 밖으로 꺼내야만 다음 폴드에 적용할 수
있으므로, **구조적으로 실수를 막는다.** 스케일러의 `fit`/`transform` 분리도 같은 원리다.

### 💡 오늘 배운 ML 개념 1가지 — L1/L2 규제 (Regularization)

**모델이 학습 데이터를 "외우는 것"을 억제해 일반화 성능을 높이는 장치.**

부스팅 트리에서는 손실 함수에 **잎(leaf)의 가중치에 대한 벌점**을 더한다.

```
최종 손실 = 예측 오차 + λ₁ · Σ|w| + λ₂ · Σw²
                        ↑ L1        ↑ L2
```

| 종류 | 벌점 방식 | 효과 |
|---|---|---|
| **L1 (Lasso)** | 가중치 절댓값의 합 | 작은 가중치를 **0으로 만든다** → 기여 없는 잎을 잘라냄 |
| **L2 (Ridge)** | 가중치 제곱의 합 | 전체 가중치를 **고르게 줄인다** → 극단적 예측 억제 |

**이번 대회에서의 의미**: Optuna가 `lambda_l1`을 기본값 ≈0에서 **4.906**까지 끌어올린 것이
튜닝 이득의 핵심이었다. 유효한 변수가 몇 개 안 되는 상황(스크린타임 3개가 gain의 70%)에서는
**나머지 변수로 만든 자잘한 분기가 전부 노이즈**다. L1 규제가 그 잎들의 가중치를 0으로 눌러
모델을 단순하게 만든 것이 성능 개선으로 이어졌다.

같은 맥락에서 `feature_fraction`도 0.8 → 0.533으로 내려갔다. **"덜 쓰는 것"이 답이었던 셈이다.**

### ✅ 가설 검증 결과

- **H1 채택** — 앙상블이 최고 단일 모델보다 **+0.000369** 높았다.
  이는 04단계 피처 엔지니어링의 이득(+0.000378)과 **맞먹는 크기**다.

  단, **놀라운 점이 있다.** 모델 간 상관이 **0.99289**로, 통상적인 기준표
  ("0.99 이상이면 앙상블 이득이 거의 없다")대로면 이득이 없어야 했다.

  *왜 이득이 났나*: **AUC는 예측값의 절대 크기가 아니라 순서로 계산된다.**
  상관 0.993은 전체적으로 비슷하게 예측한다는 뜻이지,
  **경계에 걸친 애매한 샘플들의 순서까지 같다는 뜻은 아니다.**
  AUC를 가르는 것은 바로 그 애매한 구간이고, 거기서 모델들이 서로 다르게 틀린 덕분에
  평균이 이득을 냈다. → **상관계수 기준표는 참고용 감각일 뿐 결론이 아니다.**

- **H2 기각** — CatBoost는 **가장 약하면서(−0.000942) 가장 느렸다(3,978초 = LightGBM의 18배).**
  최적 가중치에서 0.15를 받았으니 다양성 기여는 있었지만 **투자 대비 수익은 명백히 나쁘다.**
  시간이 제한적이라면 그 66분에 LightGBM을 **다른 시드로 여러 번 학습**하는 편이 나았을 것이다.

  > 캐글에서는 점수만이 아니라 **점수/시간**을 봐야 한다.
  > 대회 마감 전날 66분짜리 모델은 실험 한 번을 통째로 날리는 선택이 될 수 있다.

- **H3 기각(실질적으로)** — 가중 평균이 +0.000061 더 높았지만, 그 가중치는 **OOF에서 찾은 값**이라
  OOF에 과적합돼 있다. 차이가 폴드 표준편차(≈0.0005)의 **1/8**에 불과해 리더보드에서 뒤집힐 수 있다.
  → 노트북이 **"차이가 0.0001 미만이면 더 단순한 방법을 택한다"** 는 규칙으로 단순 평균을 자동 채택했다.

### 🐛 트러블슈팅

1. **CatBoost `CatBoostError: cat_features must be integer or string`**
   → pandas 3.0에서 `category` dtype에 `.astype(str)`을 하면 결측이 문자열 `'nan'`이 되는 게 아니라
   **NA 상태로 남는다**. `.replace('nan','NA')`가 무력했던 이유.
   → `np.where(s.isna(), 'NA', s.astype(str))` 로 확실히 치환
   → 교훈: **본 실행 전에 소규모(5만 행) 스모크 테스트**로 API 호환성을 먼저 검증하면 66분을 아낀다.
2. **05단계 실행이 80분 소요** → CatBoost의 대칭 트리 + 순서형 부스팅이 CPU에서 매우 비쌈
   → 사전에 속도를 측정하고 예산을 배분해야 했다.

### 💡 오늘 배운 ML 개념 1가지 — OOF 예측 (Out-Of-Fold Prediction)

**각 행을, "그 행이 학습에 쓰이지 않은 폴드의 모델"로 예측한 값.**

```
Fold 1 학습 → Fold 1 검증분 예측  ┐
Fold 2 학습 → Fold 2 검증분 예측  │ → 이어붙이면 전체 학습 데이터에 대한
...                               │   '편향 없는' 예측 한 벌이 나온다
Fold 5 학습 → Fold 5 검증분 예측  ┘
```

**왜 중요한가**

1. **모델 비교의 공정한 기준** — 모든 행이 "처음 보는 데이터"로서 예측된 값이라,
   학습 데이터를 외운 효과가 섞이지 않는다.
2. **앙상블 가중치 탐색의 유일한 재료** — 테스트셋에는 정답이 없으므로,
   "어떤 조합이 좋은가"를 판단하려면 **정답을 아는 OOF**가 필요하다.
3. **스태킹의 입력** — 2단계 메타 모델은 OOF 예측을 피처로 받아 학습한다.

**주의할 점**: OOF로 가중치를 최적화하면 **OOF 자체에는 과적합**된다.
이번 대회에서 가중 평균이 단순 평균보다 0.000061 높게 나온 것도 그 효과일 수 있다.
그래서 **차이가 미미하면 더 단순한 방법을 택하는 것이 안전하다.**

**전제 조건**: 모든 모델이 **같은 폴드 분할**을 써야 한다.
분할이 다르면 OOF를 서로 비교하거나 섞을 수 없다.
→ 이번 프로젝트는 `src/cv.py`의 `get_folds(seed=42)` 하나로 전 단계를 고정했다.
